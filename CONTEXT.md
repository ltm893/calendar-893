## What this stack owns
- API Gateway (idempotent — never recreated once deployed)
- Cognito App Client on User Pool (idempotent)
- Lambda: calendarEvents — GET, POST, PUT, DELETE

## What this stack imports (never creates or deletes)
- Cognito User Pool — from config.ts
- DynamoDB table named by `calendarTable` in config.ts
  Set `createTable: true` only on the first deploy of a new table name, then set it back to `false`.
  Do not use `CalendarEvents`. That name is the live DLIV table.

## IAM note
Uses explicit addToRolePolicy with table + GSI ARNs.
grantReadWriteData() on imported tables does not cover GSI ARNs —
this caused AccessDeniedException in dliv-893 and is fixed here from the start.

## API routes
| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | /calendar | Cognito | List events (from/to query params) |
| POST | /calendar | Cognito | Create event |
| PUT | /calendar/{id} | Cognito | Update event |
| DELETE | /calendar/{id} | Cognito | Delete event |

## Query params for GET /calendar
- from: YYYY-MM-DD (default: today)
- to:   YYYY-MM-DD (default: end of next month)
